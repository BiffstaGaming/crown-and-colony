## 1. How it works (plain English)

A **difficulty level** is a named bundle of tuning numbers that make the game harder or easier — how dearly founding fathers cost, how greedy the natives are, how fast recruits get pricey, where the "good/bad government" lines sit, and so on. Classic Colonization ships five levels — **very easy, easy, medium, hard, very hard** — and the game is balanced around **medium**, which is the default.

Until now these numbers were scattered through the C# as hard-coded constants. This system reads them from the rules data instead, exactly like the original: pick a level, and every one of those numbers comes from that level. **You now choose the level when you start a new game** — a "Difficulty" dropdown sits next to the world-size and land-mass pickers, offering the five classic names (Discoverer, Explorer, Conquistador, Governor, Viceroy = very easy → very hard). Your choice is **remembered in the save**, so reloading continues at the same difficulty. Leaving it on the default (**Conquistador / medium**) plays exactly as before.

**The rules, in plain words:**
- The rules data lists all five levels; each level states its own full set of numbers (the levels don't inherit from one another).
- The game selects one level (medium by default) and reads its numbers wherever a tuning value is needed.
- If the data is missing a level or a number, the game falls back to the classic medium value, so it always has something sensible to use.

**Worked example:**
> The founding-father "factor" (how much liberty each father costs) is **24** on very easy, **40** on medium, **56** on very hard. At medium a colony needs 40 liberty for its first father; on very hard it needs 56 for the same father — fathers are a bigger commitment on harder levels.

**What the player sees and does:** a **Difficulty** dropdown on the New Game screen (beside world size / land mass). Pick one of the five named levels; the game starts under that level's numbers and the choice rides the save so a reload keeps it. The default is Conquistador (medium).

## 2. Detailed rules

- **The levels** live under the spec `optionGroup id="difficultyLevels"` (which is `recursive="false"`, so its options are *not* flattened into the global option map — a level must be selected and overlaid). Each of `model.difficulty.{veryEasy,easy,medium,hard,veryHard}` restates the full option set across six fixed subgroups: `immigration`, `natives`, `monarch`, `government`, `other`, `cheat`. **There is no inheritance between levels** — each value is concrete per level.
- **Selection / overlay:** a chosen level's `model.option.*` values are read straight into `DifficultyOptions`. The default is `model.difficulty.medium`. (FreeCol overlays the level onto the base options by whole-option, last-write-wins by id; because there is no cross-level inheritance, reading the selected level's subtree directly is equivalent.)
- **Routed so far (slices 1–5):** `model.option.foundingFatherFactor` (24/32/40/48/56 — see [founding-fathers](founding-fathers.md)); `unitsThatUseNoBells` (2 — bell upkeep); the **four government limits** (medium 100/50/6/10) → `Ruleset.Difficulty.Government`, on `Colony.Government`, read by `Colony.ProductionBonus` (see [sons-of-liberty](sons-of-liberty.md)); the **natives group** — `landPriceFactor` (60), raw `nativeDemands` (2), raw `rumourDifficulty` (2), the **ship-trade penalty** `shipTradePenalty` (−30, the cut on a ship's native-sale price) and the **mission-combat probabilities** `nativeConvertProbability` (30, the capture-convert base) + `burnProbability` (6, the burn-missions chance) → `Ruleset.Difficulty.NativeConvertProbability`/`BurnProbability`, read by `Game`'s `NativeConvertProbability(owner)` / settlement-assault roll (`86d3bb1x3`) (see [natives](natives.md), [combat](combat.md), [lost-city-rumours](lost-city-rumours.md)); the **rumour percentages** `badRumour`/`goodRumour` (23/48, `percentageOption`s); the **immigration/recruit/artillery increments** `crossesIncrement`/`recruitPriceIncrease`/`lowerCapIncrease`/`priceIncrease.artillery` (2/30/0/100 — see [immigration](immigration.md), [europe](europe.md)); and the **treasure-transport fee** `treasureTransportFee` (60 — **parsed but no longer consumed for the cut**: the treasure cash-in moved to the Col1 model where the King's at-colony cut equals the player's tax rate, not this flat 60%, `86d3fb5mj`; the option is retained so the spec parses unchanged — see [treasure-train](treasure-train.md)); and the **monarch group** (`86d3c9rg6`/`86d3c9r7j`) — `monarchMeddling` (2), `maximumTax` (65), `taxAdjustment` (2), `mercenaryPrice` (65), `monarchSupport` (2), the nested **REF base composition** `refSize` (31/15/14/8) and the **war support** `warSupportForce` (4 veteran soldiers) + `warSupportGold` (1500) → `Ruleset.Difficulty.Monarch` (a `MonarchOptions` value), read by `Game.Monarch.cs` (see [monarchy](monarchy.md), [royal-expeditionary-force](royal-expeditionary-force.md)). That is **every difficulty-level-scoped option with consuming code.** The **foreign-power AI tuning** (`86d3drn56`) — the rival AI's **colony cap** (3), **Europe spend floor** (1500 gold) and **seek/travel range ladder** (8/12/16) — moved off their `Game.cs` consts onto `Ruleset.Difficulty.Ai` (an `AiTuning` value), read by the foreign-power AI in `Game.cs` (see [players](players.md)). FreeCol scales **none** of those three by difficulty (they are hardcoded in its `EuropeanAIPlayer`), so they are a **faithful subset**: held constant across the shipped levels but now data-overridable instead of hidden constants. **Derived transforms keep the raw spec value in the option and the formula in code** (rumour-dx `10−x`, demand-dx `+1`, accept-relief `(5−x)·50`, monarch-dx `1+meddling`, grace `(6−dx)·10`, tax divisor `(6−taxAdjustment)·10`).
- **Fallbacks:** a selected level absent from the spec → all values from `DifficultyOptions.ClassicMedium`; an individual option absent from an otherwise-present level → that one value from `ClassicMedium`.

| Input / condition | Result |
|---|---|
| Default load (classic spec) | `Ruleset.Difficulty` = medium values (`FoundingFatherFactor`=40, `UnitsThatUseNoBells`=2) |
| `ParseDifficulty(root, "model.difficulty.veryEasy")` | `FoundingFatherFactor`=24 |
| `ParseDifficulty(root, "model.difficulty.veryHard")` | `FoundingFatherFactor`=56 |
| Selected level not in spec | `DifficultyOptions.ClassicMedium` |
| Option missing from a present level | that option = `ClassicMedium`'s value; others parsed |

**Deviations from original 1994 / FreeCol behavior:**
- **Public surface is typed, not string-keyed.** FreeCol reads options by id (`getInteger("model.option.foundingFatherFactor")`); we expose strongly-typed properties on `DifficultyOptions` (`Ruleset.Difficulty.FoundingFatherFactor`) for compile-time call sites and per-option XML docs. The by-id lookup is an implementation detail of the parser.
- **Selection lives in the ruleset, the save carries only the level id.** The difficulty *balance* is baked into the `Ruleset` at load (the level's options parsed into `Ruleset.Difficulty`); the save stores just the chosen **level id** (`DifficultyLevel`, omitted when medium), and on load a host re-loads the ruleset under that level so the numbers match. The `Game` also carries the id (`Game.DifficultyLevelId`) so `SaveGame.From` can write it without a ruleset round-trip. A default (medium) game writes no token → byte-identical to a v45 save; a pre-v46 save loads at medium.
- **The base-`gameOptions` immigration trio is a separate follow-up.** `initialImmigration`/`europeanUnitImmigrationPenalty`/`playerImmigrationBonus` are **not** difficulty-scoped (they live in the base `gameOptions` group, identical across levels), and `initialImmigration` is a `Player` field-initializer default (`Player.ImmigrationRequired`), which can't read an instance ruleset value at construction — so routing them needs a small `GameOptions` bundle + threading the value into player creation. Split into its own task to keep this difficulty epic focused on the difficulty levels.
- **The monarch boycott factor keeps the classic-game 300, not the spec's 500.** `MonarchOptions.ArrearsFactor` is a difficulty-data field (so a variant can restate it), but it defaults to **300** and is **not** read from the spec `model.option.arrearsFactor` (whose classic medium is **500**) — the existing monarch code has always used 300, and routing it value-preservingly means keeping that number. A pre-existing FreeCol deviation, now documented on the option rather than buried in a const.
- **The foreign-power AI tuning is a faithful subset — constant across the levels.** `AiTuning` (`MaxColonies` 3, `EuropeSpendFloor` 1500, `SeekRangeLadder` 8/12/16) sits on `Ruleset.Difficulty.Ai` so a variant *can* restate it, but FreeCol exposes **no** `model.difficulty.*` option for any of the three (they are hardcoded in `EuropeanAIPlayer`: `nColonies < 3`, the `getSeekAndDestroyMission` 8/12/16 ladder; the spend floor is our own AI-budget concept, not FreeCol's). The neighbouring option that *is* difficulty-scaled, `model.option.settlementNumber`, governs **native** settlement spacing, not the rival colonial AI. So `ParseDifficulty` does **not** read these from the spec — it assigns `AiTuning.ClassicMedium` on every level (the `ArrearsFactor` pattern). The default game is byte-identical (same values, no save change); a level/variant can override them in code/data later if we choose to make the rival AI tougher.

## 3. Technical design

*Audience: developers / future sessions.*

- **`DifficultyOptions` (record):** an immutable bundle of the routed tuning values (grown slice by slice), plus `DifficultyOptions.ClassicMedium` — the fallback and default source of truth. Pure/immutable (ADR-009): parsed once, no state, no RNG. Nested value records group related options: `GovernmentLimits` (the four SoL/tory limits) and `MonarchOptions` (the `model.difficulty.monarch` group + `refSize` + the boycott factor), each with its own `ClassicMedium`.
- **`MonarchOptions` (record):** the home-nation King's tuning — `Meddling`/`MaximumTaxRate`/`TaxAdjustment`/`MercenaryPricePercent`/`MonarchSupportLevel` (the SUPPORT_LAND tier index 0-4, `86d3fq0c7`) from the `monarch` group, the four REF base counts from the nested `refSize` `unitListOption`, the **war support** `WarSupportForce` (a `MonarchSupportUnit` list, from the `warSupportForce` `unitListOption`) + `WarSupportGold` (`86d3c9r7j`), and `ArrearsFactor` (default 300, not parsed). Read via `Ruleset.Difficulty.Monarch` by `Game.Monarch.cs`. `MonarchSupportUnit(UnitTypeId, RoleId, Number)` is a Specification-level value type (mirrors `EuropeanStartingUnit`) so `MonarchOptions` stays free of any `GameSession` dependency. See [monarchy](monarchy.md), [royal-expeditionary-force](royal-expeditionary-force.md).
- **`AiTuning` (record):** the foreign-power (rival) AI tuning — `MaxColonies` (the colony cap), `EuropeSpendFloor` (the Europe spend reserve) and `SeekRangeLadder` (the offensive 8/12/16 range gates, an `IReadOnlyList<int>`). Its own `ClassicMedium` (3 / 1500 / `[8,12,16]`). Read via `Ruleset.Difficulty.Ai` by the foreign-power AI in `Game.cs` — the founding checks use `Ruleset.Difficulty.Ai.MaxColonies`, `RunForeignPowerEuropeSpend` reads `AiEuropeSpendFloor` (now an instance property over `Ruleset.Difficulty.Ai.EuropeSpendFloor`), and the seek-and-destroy loops read `SeekRangeLadder` (an instance property). `Game.MaxAiColonies` is now an `internal static` alias over `DifficultyOptions.ClassicMedium.Ai.MaxColonies`, preserving the test-facing API while the live checks read the per-ruleset value. **Faithful-subset:** FreeCol exposes no `model.difficulty.*` option for any of the three (hardcoded in `EuropeanAIPlayer`), so `ParseDifficulty` assigns `AiTuning.ClassicMedium` rather than reading the spec — every level is identical. See [players](players.md).
- **`ExpertStartingUnits` (bool, `86d3e4br5`):** whether each colonial power lands the **expert** variant of a starting-unit slot (spec `model.option.expertStartingUnits`, in the level's `immigration` sub-group; classic **true** on veryEasy/easy, **false** on medium+; `ClassicMedium` false). Parsed via the new `BoolOption(id, fallback)` helper. Read by `EuropeanNationType.StartingUnitsFor(expert)` (consumed by `Game.SpawnHumanStartingUnits`/`LandForeignPower`) — when on, a slot with an expert variant (e.g. the default soldier) places the expert (veteran soldier) instead of the free-colonist version. Default medium false ⇒ the default game's roster is unchanged. See [players](players.md).
- **`Ruleset.ParseDifficulty(XElement root, string levelId = "model.difficulty.medium")`:** mirrors the `ParseCalendar`/`ParseFatherAgeYears` idiom but with one **critical divergence** — difficulty options are restated under every level group, so it **first selects the level subtree** (`root.Descendants("optionGroup").FirstOrDefault(id == levelId)`) **then** searches *within* that subtree (`level.Descendants("integerOption")…`). Searching the whole document would match the first level (`veryEasy`) — a deliberate test (`ParseDifficulty_DefaultsToMedium_NotTheFirstLevel`) guards against exactly that. A local `IntOption(id, fallback)` helper rooted at the level reads each value, each falling back to `ClassicMedium`; a parallel `PctOption` variant reads `percentageOption` elements (the rumour percentages) — same `value` attribute, different element name; a `BoolOption(id, fallback)` variant reads `booleanOption` elements (`expertStartingUnits`, which lives in the level's `immigration` sub-group — `Descendants` reaches into it); and a `RefSize(unitOptionId, fallback)` variant reads the `<number value="…"/>` inside each `<unitOption>` of the `refSize` `unitListOption` (the only nested option group routed). Dotted ids (`model.option.priceIncrease.artillery`) match as opaque strings. A missing level returns `ClassicMedium` wholesale.
- **Wiring:** `Ruleset` gains a trailing ctor param and a `public DifficultyOptions Difficulty { get; }` property, assigned alongside `Calendar`/`FatherAgeYears`. `Load` calls `ParseDifficulty(root)` next to the calendar parses.
- **Consumers:** `Game` already holds `Ruleset`, so each migration is mechanical — e.g. `TotalFoundingFatherCost` reads `Ruleset.Difficulty.FoundingFatherFactor`, and the bell-upkeep step reads `Ruleset.Difficulty.UnitsThatUseNoBells`. **`Colony` is deliberately kept free of a `Ruleset` dependency** — when the government limits are routed (slice 2) they will be *passed into* `Colony.ProductionBonus`, not pulled from a ruleset reference, to keep pure colony logic decoupled.
- **Determinism / save (slice 6):** still no RNG and the balance is re-derived from the (versioned) ruleset + selected level at load. The save adds **one** field — `DifficultyLevel` (the level id), additive and **omitted when medium** — riding the **v46** bump. A default game writes no token → byte-stable soak. The chosen level changes balance *constants* only; it does **not** reorder any RNG draw, so a fixed-seed game at a non-default level is still fully deterministic (it just plays by different numbers).
- **Selection + persistence wiring (slice 6):** the `DifficultyLevels` registry (data-not-code, mirroring `WorldSizeOptions`/`GameVariants`) lists the five levels with player-facing names (Discoverer/Explorer/Conquistador/Governor/Viceroy) and the medium default. `Ruleset.Load*`/`GameVariant.LoadRuleset` take an optional `levelId` (default medium) and stamp `Ruleset.DifficultyLevelId`. `Game.New` takes a matching `difficultyLevelId` (default medium) recorded on `Game.DifficultyLevelId`. The new-game flow forwards the picker choice via `GameController.PendingDifficulty` (mirroring `PendingWorldSize`/`PendingLandMass`); the load paths (`LoadFrom`/`QuickLoad`) re-load the ruleset under `save.DifficultyLevelOrDefault`. The picker itself is presentation-only (`NewGameDialog`, ADR-006) — it only forwards a `DifficultyLevel`.
- **Derived-vs-raw rule (later slices):** where a constant is a *transform* of a spec value (e.g. the lost-city `rumourDifficultyDx` = `10 − rumourDifficulty`), store the **raw** spec value in `DifficultyOptions` and keep the transform in code, so the option matches the spec.
