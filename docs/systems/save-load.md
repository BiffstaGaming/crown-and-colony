## 1. How it works (plain English)

Press **F5** to save, **F9** to load. A save captures everything — the map, the units, whose turn it is, and even the game's hidden "dice position" — so a loaded game continues *exactly* as if you'd never stopped: the same future battles, the same future maps. Saves are readable JSON files (handy for debugging and bug reports).

## 2. Detailed rules

- A save restores: turn, map (terrain per tile), every unit (id, **type**, position, movement left), **explored tiles (fog of war)**, RNG state.
- Loading an interrupted game then continuing produces **identical outcomes** to never having saved (tested).
- **The unit-id counter is monotonic and persisted (v54+).** Each new unit gets the next id from a counter that only ever counts up — it is **not** rewound when a unit is destroyed, so after a unit dies the counter can sit *ahead* of `max(surviving unit id) + 1`. The save persists this counter (`SaveGame.NextUnitId`) so a save/load round-trip resumes the exact same id sequence; it is **omitted** whenever it equals `max + 1` (the common case → byte-identical to v53), so only a game that has destroyed its highest-id unit writes the field. Pre-v54 / omitted saves re-derive the counter from the surviving units exactly as before (`Restore` then clamps a loaded value up, never below a surviving id, so it can't collide). *This closed a latent resume-identical gap: before v54 a game that had lost its highest-id unit resumed with a counter one-or-more lower than the uninterrupted run, so the next unit created got a different id and the two diverged.*
- Saves carry a format `Version` (the authoritative source is `SaveGame.CurrentVersion`); older saves still load with sensible defaults for fields that didn't exist yet (see the changelog), and v1 saves default units to free colonists and reveal fog around units.
- **Old-save guarantee (you keep your save across a code update).** `Restore` **never rejects on version** — there is no version gate that throws; it simply defaults every field an older save lacked. Combined with the additive + omit-when-default format, this means **new code always loads an old save**: that is exactly the user's case (you update the game, then load the save you made on yesterday's build). *The inverse is not, and cannot be, supported:* an **older** binary cannot load a **newer** save (it has no field to read the newer data into). That asymmetry is fine — you only ever move the code forward.
- **Old-save guarantee, proven by stored fixtures + down-version loads.** A *round-trip of a current game* can't prove backward-compat (it always writes today's shape), so two complementary techniques pin it (`Persistence/SaveBackwardCompatTests.cs`, plus the per-version field-by-field cases in `SaveGameTests.cs`):
  - **Hand-authored, true old-format files.** `fixtures/save-v41.json` (a tiny map, one player, one colony, two units, with **none** of the post-v41 fields) and `fixtures/save-v40.json` (a v40 save, predating the rebellion lifecycle) are committed **frozen** — a current `From()` can never reproduce their shape. `StoredV41Save_LoadsCleanlyOnCurrentVersion_AndIsPlayable` and `HandWrittenV40Save_LoadsCleanlyOnCurrentVersion_AndIsPlayable` load each on the current ruleset and assert every newer field defaulted safely (regions re-derived + undiscovered, attrition 0, no unit name, Active orders, no Spanish succession, no pending monarch demand, default difficulty, no peace turns, …) **and** that the loaded game is playable (an `EndTurn` runs and advances the turn). Both fixtures also pre-date `Players[]` (v20), so they double as a check that the legacy flat-field fold still produces one human.
  - **Synthetic down-version loads across a realistic game.** `DownVersionedSave_LoadsWithoutThrowing_AndKeepsCoreStateIntact` takes a fully-populated current save (colonies, rivals, natives, market movement, fog), stamps an older `Version` (45 / 50 / 55) and strips the top-level fields added after it, then asserts `Restore` tolerates the older shape and the core state (turn / units / colonies / gold) survives and the game stays playable. This exercises each historical load path against real game state rather than a bare fixture, and can't drift since the stripping is keyed off the version.
  - As `CurrentVersion` keeps climbing, these tests guard the whole additive-migration promise — keep the fixtures frozen (do not regenerate them from a newer game).
- **Player-scoped state (v20+)** — treasury/tax, the per-player market, liberty/Congress, immigration + the Europe dock, the per-player RNG stream, and explored fog — is stored in a `Players[]` array (the human + the foreign powers + native nations; see [players](players.md)). The load path is chosen by version: a v20+ save reads `Players[]`; a v19-and-earlier save **folds** the old flat top-level fields into a single human player. As of **FP-7** a v20 save writes player state **only** in `Players[]`; the legacy flat top-level fields are no longer written (the format version stays **20** because the v20 load path was already `Players[]`-only, so new v20 saves are just smaller). The flat field *properties* remain on the record (read-only) so ≤v19 saves still fold them into one human player, and pre-FP-7 v20 saves (which carry both) still load via the `Players[]` arm — the flat fields are ignored whenever `Players[]` is present. From **FP-5** these per-player fields actually diverge in real games (each foreign power moves its own market, banks its own gold/liberty/immigration, fills its own dock, advances its own RNG) and all of it round-trips byte-identically — the soak proves a 200-turn active-economy game re-saves identically. On load, each colonial player's Europe dock is **topped up** to its full set: a no-op for a full FP-5 dock (no RNG drawn, so byte-stable), a fresh draw for an older save's empty foreign dock (a foreign power loaded from a pre-FP-5 save can then recruit).
- Each unit also restores its **owner and equipment** (v18+): the owning native nation (null = the player) and its military role + role count; pre-v18 saves load every unit player-owned and unarmed (tested). Native braves persist through the unit list via the owner field — no separate collection — so a saved game's garrisons come back intact. A ship **damaged in combat** restores its **repair countdown** (v21+): turns left repairing in Europe (0 = healthy); pre-v21 ships load healthy.
- The map restores its **Lost City Rumours** (v25+): the tiles holding an unexplored rumour, as a row-major index list (`SaveGame.Rumours`), omitted when none so a rumour-free game stays byte-identical to v24; pre-v25 saves load with no rumours. Placement is gen-time only (a dedicated RNG stream, never resumed), so the save just lists the surviving tiles. See [lost-city-rumours](lost-city-rumours.md).
- The map restores its **tiles bought/taken from the natives** (v26+): a row-major index list (`SaveGame.ClaimedTiles`), omitted when none so a no-purchase game stays byte-identical to v25; pre-v26 saves load with none. Native tile *ownership* is otherwise **derived** (recomputed from the settlements, not saved); this claimed-tiles override is the one piece that persists, so the re-derivation on load never re-claims a tile you already bought. See [natives](natives.md).
- A colony restores its **ordered build queue** (v24+): the queue **front** is the long-standing `CurrentBuild` field; the **tail** (everything after the front) rides in `SavedColony.BuildQueueRest`, omitted entirely when the queue holds ≤ 1 item — so a single-building or idle colony stays byte-identical to v23. A pre-v24 save loads its lone `CurrentBuild` as a one-item queue. See [colonies](colonies.md).
- A save also restores all **native settlements** (v14+): id, owning nation type, settlement type, capital flag, position, size, taught skill, plus their **interaction state** (v16+): alarm, visited flag, skill-consumed flag, and **wanted goods** (v17+). A settlement **destroyed by assault (v19+)** is simply absent from the saved list — there is no new field; its plunder is already folded into the saved gold.
- A save restores the **message log** (v59+): the per-turn player notices the dismissible turn-message panel showed and then forgot, so the re-openable log survives a reload (`SaveGame.MessageLog`, each row a turn + category + the already-formatted text). The strings are formatted presentation-side (ADR-006), so the *controller* — not `SaveGame.From` — attaches the field on save and re-groups it per-turn on load. Omitted when the log is empty, so a fresh game stays byte-identical to v58 and pre-v59 saves load with an empty log. The log feeds no game evolution, so a reloaded game continues on the identical random sequence. See [turns](turns.md).
- A player restores the turn the **King last raised its tax** (v60+): `SavedPlayer.LastTaxRaiseTurn`, the stamp that enforces the inter-raise tax grace period (the King won't demand another rise until the cooldown elapses). Persisting it means a reload mid-cooldown can't reset the clock and let the King raise again immediately (ADR-009 determinism). Omitted when null — the King has not yet raised this player's tax, which holds for every fresh game and the whole early game — so a game with no tax raise yet stays byte-identical to v59; pre-v60 saves load with no cooldown active. See [monarchy](monarchy.md).
- A save records its **game variant** (v15+; e.g. `classic`) so it reloads under the matching ruleset (ADR-018); pre-v15 saves resolve to the default variant. See [game-modes](game-modes.md).
- Saves reference terrain by ruleset id — loading needs the matching ruleset; unknown ids fail loudly.

**Deviations:** our own JSON format by design; no FreeCol save compatibility planned.

## 3. Technical design

- `SaveGame` (record): pure DTO snapshot; `From(game)` / `Restore(ruleset)` / `ToJson()` / `FromJson()`. System.Text.Json, indented output.
- RNG round-trip via `RandomState` (ADR-009) — the linchpin of resume-identical behaviour.
- Quicksave path: `user://quicksave.json` (Godot user dir); file I/O lives in presentation (`GameController`), serialization in GameLogic — keeps GameLogic free of file-system concerns.
